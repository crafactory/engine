# Crafactory Engine v0.5.0 阶段说明

> **Historical v0.5.0 stage note.** Current plugin/API status is in
> [PLUGIN-SUPPORT-MATRIX.md](PLUGIN-SUPPORT-MATRIX.md) and
> [PLUGIN-COMPATIBILITY.md](PLUGIN-COMPATIBILITY.md).

本轮是原创 MIT 的阅读渲染兼容子集，不是完整 Obsidian 复刻。开发和构建通过 Pull Request，须等待 CodeRabbit 完成审查、修复问题并复审，才能合并和继续下一阶段；分支构建不是正式发布。

新增阅读模式的排序后处理器、指定语言代码块处理器、MarkdownRenderChild 子组件生命周期及 MarkdownRenderer 静态安全渲染。子组件容器移除、阅读根替换、插件停用会触发清理；迟到的异步回调只写入旧的脱离 DOM 根，不污染新文档。整篇阅读主机提供路径、frontmatter 和 docId，精确区段行号返回 null，不伪造映射。

[功能清单](https://github.com/crafactory/engine/blob/main/docs/FEATURE-CHECKLIST.md)包含 109 个稳定编号、全部 29 个核心插件和 44 个限定验收点。插件运行时默认 Worker 仍为 27 个子集导出，主动授权的 Trusted renderer 为 45 个；导出存在不代表所有成员、重载、事件和时序兼容。

真实插件使用固定版本和 SHA-256 校验的原始发布文件，没有复制进应用或仓库。Reading Time 保留八个限定流程；Calendar 与 Advanced Tables 仅启动成功；Dataview 的首个阻塞推进到 App.appId，仍启动失败；Templater 仍是通用类加载错误。Worker 中五个插件仍全部失败。详见[分模式实测](https://github.com/crafactory/engine/blob/main/docs/TRUSTED-RENDERER-PLUGIN-TESTS.md)和[兼容报告](https://github.com/crafactory/engine/blob/main/docs/PLUGIN-COMPATIBILITY.md)。

九个新增原生桌面用例覆盖排序与源码字节、真实子组件事件和数据、静态渲染、迟到回调隔离、子组件启动失败、渲染等待期间停用、永不结束的子组件启动、停用后迟到完成、旧上下文不能破坏新会话组件及卸载挂起时的全局事件清理。启动和卸载各最多等待一秒后继续主插件清理，旧子组件未真正完成前不允许被新会话收养；已经停用后补注册的 Component 资源立即清理，嵌套子组件不会重新启动。同一个对象重载会等待旧启动与完整卸载结束，旧上下文无权卸载后继会话的子组件。旧资源在卸载开始时固定并立即调用清理，等待中的用户钩子或另一个清理 Promise 不会延迟受管理事件的移除；异步完成顺序允许交叠，不宣称参考时序等价。这不是强制中断，任意可信代码仍可继续直接副作用或冻结主线程。深浅色桌面阅读与窄屏弹窗经过交互和视觉检查；具体测试数量、CI 和审查结果以 PR 最终证据为准，不把未执行的打包验收写成通过。

Trusted renderer 不是沙箱，可访问界面和 Vault bridge，不能强制中断主线程。精确区段、嵌入上下文、Live Preview 处理器、静态渲染递归处理器、完整插件/API、原生移动端及 Windows/macOS 安装运行仍未验收。Linux 安装包仍未签名，测试重要笔记前请先备份。

审查期间还修正了生命周期钩子内部重复调用的自等待、排队重载取消、嵌套启动失败，以及每日笔记创建后延迟焦点抢走模板输入的问题。新增第十个原生用例验证插件启动等待时即可撤销处理器并拒绝迟到注册；跨笔记测试明确从 Test.md 切到 Next.md 后再释放旧回调。撤销处理器不代表强行终止插件：任意启动或卸载钩子不结束时，完整关闭与 Vault 切换仍可能等待。

另补两个直接注册表单元用例，验证代码块处理器同步抛错和异步拒绝时先恢复原始代码块，再上报同一个错误，不依赖界面重新渲染掩盖空容器。
